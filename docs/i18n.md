# 多國語言（繁體中文／英文）

## 怎麼運作

- 自建輕量實作，不加套件：`src/i18n/` 底下有 `core.js`（語言判定與翻譯）、`format.js`（數字與日期）、`I18nProvider.jsx`、兩份字典 `zh-TW.js` 與 `en.js`。
- 字典是扁平 key（`group.menu.invite`），參數用 `{name}`。缺 key 時先退回 zh-TW，再退回 key 本身；開發模式會在 console 警告。
- 頁面用 `const { t, fmt, lang } = useI18n()`：`t('key', { name })` 取字，`fmt.num()`、`fmt.date()` 等格式化數字與日期。
- 兩份字典的 key 與佔位符必須一致（`npm test` 會檢查）。新增字串時兩份都要加。
- **程式裡不能再寫死中文**：`npm run check:cjk` 掃描 `src` 的字串、template 與 JSX 文字（註解不算），目前必須是 0；`npm test` 也會執行同一個檢查。例外：`i18n/zh-TW.js`、`i18n/legacy.js` 與測試檔。
- `console` 訊息一律用英文，不進字典。

## 語言怎麼決定

順序：網址 `?lang=`（會記住）→ localStorage `catsplit-lang` → （`EN_READY` 為 false 時固定中文）→ LIFF 語言 → 瀏覽器語言 → 繁體中文。`zh` 開頭視為繁體中文，其他語言都用英文。

語言下拉選單在設定頁（頭像選單第一項「設定」），所有人都看得到。

## 上線開關 `EN_READY`

`src/i18n/core.js` 的 `EN_READY`：

- `false`：沒手動選過語言的人一律是中文；手動選英文（設定頁或 `?lang=en`）的人看得到英文版。
- `true`：沒手動選過語言時，依 LIFF 與瀏覽器語言自動選語言。

切換時要**單獨一個 commit**，出問題時只要把它改回 `false` 即可，不影響其他程式。

## 資料與顯示拆開

分類、付款方式與最新動態在資料庫存的是代碼，畫面才轉成目前語言：

| 資料 | 新資料存什麼 | 舊資料 |
|---|---|---|
| 分類 `category` | `food`、`transport`…；自訂分類是原字串 | 中文（例如「餐飲」） |
| 付款方式 `paymentMethod` | `cash`、`jkopay`… | 中文名稱 |
| 最新動態 `lastActivity` | `{ by, name, type, title, toName }` | `{ by, name, text }` |

`src/i18n/legacy.js` 負責讀取時把舊中文對應成代碼（`normalizeCategory`、`normalizePaymentMethod`、`describeActivity`），所以舊資料不用遷移也能正常顯示。`WRITE_CODES` 為 true 時才寫代碼；改回 false 會恢復寫入舊中文，讀取端兩種都認得。

**待辦**：清掉所有舊資料後，刪除 `legacy.js` 的舊對照與 `WRITE_CODES`（見 `todo.md`「收尾：移除舊資料相容層」）。

## 分享連結預覽

LINE 的分享卡與連結預覽由雲端函式 `sharePage` 產生，語言看網址的 `?hl=`，**只認 `en`**，其他一律中文。App 內分享時，目前語言是英文才會在連結加上 `?hl=en`。刻意不用 `?lang=`，避免與 App 內手動選語言的參數混在一起。文字在 `functions/sharePreview.js`（含測試）。

## 條款與隱私權政策

英文版是獨立的靜態頁 `public/terms.en.html`、`public/privacy.en.html`，內容翻譯自中文版，**兩者不一致時以中文版為準**（頁面上已註明）。修改中文版時要同步更新英文版與頁面上的日期。首頁的連結依目前語言切換。

## 已知限制

- Flex 訊息（轉帳、新增支出）與邀請文字依**發送者**的語言產生，收到的人語言可能不同。
- 銀行名稱（`bankCodes.json`）維持台灣的中文名稱。
- 雲端函式 `detachFromGroup` 把退出的成員轉成訪客名字時，預設名稱「前成員」是中文，因為它會存進資料庫給所有人看。
- 英文介面還沒有人工逐頁檢查過窄螢幕（320／360px）的版面溢出，上線前請照 `.omc/plans/p1-i18n.md` 的檢查位置清單看一遍。
