# 個人記帳

底部導覽列「記帳」進入個人帳本。只有本人看得到；訪客不能使用（導覽列灰色並提示）。設計當時的決定見 [P12 spec](../superpowers/archive/2026-11-14-p12-personal-ledger-design.md)，實作順序見[計畫](../superpowers/archive/2026-11-24-p12-ledger-plan.md)（皆已封存；以本文為準）。

**已上線（2026-11-25）**
- **記帳**：多個帳本、帳戶與多幣別帳目（支出、收入、轉帳）、月曆主頁（紅色假日）、記帳面板與常駐數字鍵盤、編輯與刪除。
- **帳戶**：帳戶管理、淨資產（重新計算餘額在設定頁「資料」分頁）。
- **圖表**：分類占比、近 6 個月趨勢、年度檢視、預算進度。
- **設定頁四個分頁**（頁面頂端不顯示目前帳本與統計幣別，帳本名稱與統計幣別在帳本選單看）：基本（三個入口：固定收支與轉帳、預算、類別，點進去是各自的獨立內頁 `/ledger/settings/recurring`、`/budget`、`/categories`，入口右側顯示現況摘要；類別內頁用「支出／收入」切換）、進階（週開始日、月開始日、年開始月、假日調整）、分帳（連結群組、同步、匯入）、資料（匯出 CSV、重新計算餘額、備份與還原）。
- **帳本選單**：切換、新增、改名、刪除。

## 結構

```
users/{uid}/ledgers/{ledgerId}                       帳本（名稱、統計幣別、期間與預算設定）
users/{uid}/ledgers/{ledgerId}/accounts/{accountId}  帳戶（單一幣別、餘額）
users/{uid}/ledgers/{ledgerId}/transactions/{id}     帳目（收入、支出、轉帳）
users/{uid}/ledgers/{ledgerId}/groupLinks/{groupId}  連結的分帳群組
users/{uid}/ledgers/{ledgerId}/trips/{tripId}        旅程（匯率頁；帳目用 tripId 歸在旅程底下）
users/{uid}/ledgers/{ledgerId}/categories/{id}       類別（自訂與改過的清單，支出類別可帶月預算）
users/{uid}/ledgers/{ledgerId}/recurring/{id}        固定收支與固定轉帳的規則
```

欄位、rules 與取捨見 [資料模型](data-model.md) 與封存的 spec 第 1 節。第一次進入會自動建立 id 固定為 `default` 的「我的帳本」（TWD）與一個「現金」帳戶；新增帳本時同樣會建立「現金」帳戶（幣別 = 統計幣別）。

## 金額與幣別

- 每筆收入與支出記**實際花的幣別與金額**（`currency`、`amount`）、當下匯率與換成帳本統計幣別的金額（`exchangeRate`、`baseAmount`）。統計只加總 `baseAmount`，之後不重算。
- 帳戶幣別與帳目幣別不同時，另記對帳戶餘額的影響 `accountAmount`（由 `accountRate` 估算，可手動改成實際扣款金額）。帳戶幣別等於統計幣別時，扣款匯率直接沿用統計匯率，不用輸入第二次。
- 轉帳記轉出金額 `amount` 與轉入金額 `toAmount`，不計入收支，跨幣別時兩者不同。
- 帳戶 `balance` 在記帳、編輯、刪除時於同一個 batch 用 `increment` 更新（增量由 `balance.js` 算）。設定頁「資料」分頁的「重新計算餘額」會讀取整個帳本的帳目，依「期初餘額＋帳目」重算每個帳戶並寫回（快照帳戶不處理）。
- 匯率用 `useExchangeRate`（open.er-api.com），抓取失敗時要手動輸入。

## 旅程帳目與匯率頁

匯率頁（`/fx`）的設計與取捨見 [`2026-11-26-fx-page-design.md`](../superpowers/archive/2026-11-26-fx-page-design.md)（已封存；以本節為準）。已上線（2026-11-26）：

- **旅程垃圾桶**：旅程編輯面板的「刪除旅程」只在旅程文件寫入 `deletedAt`（客戶端時間，`trashTrip`），帳目不動、可隨時還原（`restoreTrip`）。垃圾桶中的旅程不出現在旅程列表與旅程選單、不能記帳，帳目一律不計入個人統計（即使開了「計入個人統計」），但**帳戶餘額仍包含這些帳目**，永久刪除時才退回。垃圾桶頁（`/fx/trash`，從設定頁或旅程列表進入）列出旅程、帳目筆數（`getCountFromServer`）、刪除日期與剩餘天數，每趟可「還原」或「永久刪除」（先預覽筆數與各帳戶退回多少，`planTripPurge`）。
- **永久刪除（`trashPurge.js` 的 `purgeTrip`）**：帳目分批（100 筆）處理，**每批在一個 Firestore 交易裡**：先讀旅程確認還在垃圾桶（別處還原了就停手），再讀這批帳目、只對還存在的刪除並以 `increment` 退回帳戶餘額（帳戶已不存在就略過），全部刪完才刪旅程文件。因此兩個分頁或自動與手動同時執行也只會退一次，中途失敗或預算用完時旅程仍在垃圾桶、下次接著處理。`db` 以參數傳入，整合測試 `firestore-tests/tripPurge.rules.mjs` 用模擬器加真正的 rules 跑（退款、分批、並發、中途還原、帳戶不存在、別人不能刪）。
- **滿 30 天自動永久刪除**：沒有後端排程，所以和固定收支一樣在開啟匯率頁時補做（`TrashAutoPurge`）：只處理目前帳本、最早刪除的先處理、每次最多刪 1,000 筆帳目（其餘下次開啟再處理）、每趟旅程獨立處理，刪除後提示「已自動清除 N 趟過期的旅程」。沒開匯率頁就不會刪，垃圾桶本來就是安全網。

- **計算機設定（`/fx/settings`）**：小數位數（0–3）、預設金額、顯示幣別符號、免稅百分比（預設 10）、刷卡手續費百分比（預設 1.5），選了或輸入完立刻儲存到雲端 `users/{uid}/settings/fx`（`useFxSettings` 即時訂閱、`saveFxSettings` 以 merge 只寫有改的欄位）；輸入不合法會提示並還原。「還原預設值」刪掉整份文件。欄位驗證與合併預設值是 `fxSettings.js` 的純函式（缺少或壞掉的欄位一律退回預設值），rules 逐欄驗證（`firestore-tests/fxSettings.rules.mjs`）。文件讀取失敗（例如 rules 還沒部署）時用預設值，不擋住計算機。訪客沒有設定頁，用預設值。
- **自訂匯率（`/fx/settings/rates`）**：設定頁的「自訂匯率 N 種」進入，列表點一筆改匯率、垃圾桶鈕刪除、「新增」開底部面板（`CustomRateSheet`：從、換成、匯率；選到和另一邊相同的幣別會自動對調）。資料是 `customRates`（鍵 `JPY_TWD` 表示 1 JPY = ? TWD，優先於 API 匯率，最多 20 組；rules 只檢查數量，值是否為正數由前端驗證）。**同一組幣別只留一筆**：新增 A→B 會移除 B→A，因為反向本來就自動取倒數，兩筆並存會互相矛盾（`setCustomRate`）。整個 `customRates` 欄位以 `mergeFields` 一起寫入，才能真的刪掉一組（單純 merge 會留下舊的鍵）。計算機上用到自訂匯率的列（輸入列與該列之間，或與實付幣別之間）會標示「自訂」（`isCustomPair`）。

- **計算機（`/fx`）**：頂部藍色條是全站共用的 `UserHeader`（頭像、招呼語、帳號選單；右側圓鈕放旅程明細與設定，下方膠囊鈕選旅程），和入口、分帳列表、目標、記帳主頁一致。`FxCalculator`（畫面與計算）、`FxCalculatorPage`（外層：目前旅程、換算列、記帳）、`FxKeypad`（鍵盤，算式規則沿用 `ledger/expression.js`）、`TripPicker`（頁首旅程選單）、`fxMath.js`（匯率換算與實付計算，純函式）。匯率用 `useFxRates`：以 USD 為 1 的一份 open.er-api.com 表（記憶體快取 1 小時）算出任兩種幣別，抓不到的列顯示「—」並可重試；這是參考匯率，不是銀行或信用卡實際的結匯價。
- **實付**：換算列下方的「免稅 −10%」與「刷卡 +1.5%」兩個鈕，先免稅、後刷卡：免稅 = 金額 − 金額 ÷ 1.1（價格含稅 10%，不是乘 0.9）、刷卡手續費 = 免稅後金額 × 1.5%，實付幣別用鍵盤上方的幣別鈕選。百分比目前是預設值，第五階段才可在設定頁修改。
- **記帳（收據鍵）**：實付金額（含免稅與手續費）、實付幣別、計算機上的匯率（`preset.baseRate`）、來源 `fx` 預填到同一個記帳面板；儲存後計算機清空（`preset.onSaved`），保留旅程與換算列。沒選旅程時收據鍵灰色，按了會提示並開旅程選單；訪客只有純換算。
- **存放位置**：目前選的旅程存本機（`fxLocalPrefs.js`）；換算列與實付幣別有旅程時存在旅程文件上（`rows`、`payCurrency`），沒有旅程或訪客時存本機。

- **旅程頁在 `src/features/fx/`**：`/fx` 目前是旅程列表（`TripListPage`，進行中與已封存）、`/fx/trips/:tripId` 是旅程明細（`TripDetailPage`：總花費卡、依日期分組、每日小計）。`FxShell` 用 `LedgerProvider lite` 包住路由，訪客只看到提示。新增與編輯旅程用 `TripSheet`（名稱、旅遊幣別、出發與回程日、是否計入個人統計、封存）；寫入在 `fx/data.js`，驗證與列表整理在 `fx/trips.js`，總花費與分組在 `fx/tripSummary.js`（皆為純函式，有測試）。
- **旅程記帳**：明細頁底部「記帳」呼叫 `openEntry(undefined, { tripId, currency, date })`，同一個記帳面板預填旅程與旅遊幣別，面板上方標示「旅程：名稱」；點帳目列用同一個面板編輯。旅程可封存（收到列表最下方）或刪除（移到垃圾桶）。
- **總花費**＝旅程內支出扣掉收入（統計幣別）；旅遊幣別的小計只加幣別相同的帳目。

- 帳目可帶選填欄位 `tripId`，指向 `trips/{tripId}`（`name`、`currency`、`countInStats`、`deletedAt`、`rows`、`payCurrency`…）。沒有這個欄位就是一般帳目，既有資料不用遷移。
- **旅程帳目預設不出現在月曆與個人統計**：`hooks.js` 的 `useMonthTransactions`、`useYearTransactions`、`useMonthsOnce` 在回傳前用 `summary.js` 的 `isPersonalTx(tx, hiddenTrips)` 過濾。要隱藏的旅程（`hiddenTripIds`）＝沒開 `countInStats` 或有 `deletedAt`；找不到旅程的 `tripId` 視為一般帳目。旅程載入前三個 hook 回傳 `null`（載入中）。`LedgerShell` 訂閱 `trips` 並把 `hiddenTrips` 放進 Context。
- **帳戶餘額照常計算**，「重新計算餘額」也包含旅程帳目。
- 備份帶 `trips` 與 `tripId`（舊備份沒有 `trips` 仍可還原）；CSV 最後多一欄「旅程」。

## 記帳面板

從底部彈出：支出／收入／轉帳切換 → 日期（整行，點了跳出日期選擇）→ 類別與帳戶下拉 → 備註 → 金額列（幣別、算式與結果）→ 換算資訊 → 數字鍵盤 → 「再記一筆／儲存」。

- 金額最先：有 `+ − × ÷` 時主按鈕變「＝」，先算出結果，再按一次才儲存。
- 日期預設帶月曆選取的那天；帳戶與類別預設帶最近用的（存在本機，每個帳本各一份）。
- 手動帳目沒有標題欄位：列表顯示備註，沒有備註就顯示類別。
- 編輯舊帳時沿用當時存的匯率；刪除會把對餘額的影響退回去。

## 帳戶管理

- 帳戶頁右上「＋」新增：名稱、種類、幣別（建立後不可改）、期初餘額（信用卡欠款填負數）。點帳戶可編輯名稱、種類、期初餘額；改期初餘額時目前餘額跟著加上差額（`increment`）。
- **封存**：不能再記帳，帳目與餘額保留，淨資產仍計入；**刪除**只限沒有帳目的帳戶（查 `accountId` 與 `toAccountId`，rules 無法擋，只在前端）。最後一個可用帳戶不能封存或刪除；最多 30 個帳戶（前端限制）。
- **淨資產**：外幣帳戶以 `open.er-api.com` 的目前匯率換成統計幣別，取不到匯率的幣別不計入並提示；快照帳戶不計入。
- **重新計算餘額**（設定頁「資料」分頁）：讀整個帳本的帳目，與記錄的餘額不同的帳戶才寫回。

## 圖表

- 主頁右上圓鈕進入 `/ledger/stats`。只加總 `baseAmount`（統計幣別），轉帳不計。
- 選定月份沿用即時訂閱；趨勢的其他月份各讀一次並快取在頁面記憶體，切換月份只補讀新的一個月，**沒有彙總文件、沒有新索引**。代價是讀取量隨帳目數增加：每天 20 筆時，看一次趨勢約讀 3,000 筆，使用者少時遠低於免費額度。
- 頁面開著時在別的月份新增帳目，趨勢的快取不會更新，離開再進來即可。

## 年度檢視

圖表頁標題下可切換「月／年」。年檢視一次性 `getDocs` 讀整個年期間的帳目（單一範圍查詢，不訂閱；切換年度才重讀），畫 12 個月的趨勢與整年分類占比；每天記 20 筆的人，看一次約讀 7,000 筆，目前用量遠低於免費額度，之後有需要再優化。月視圖不變。年度標題在年開始月或月開始日不是 1 時顯示範圍（例如 2026/04/01–2027/03/31）。

## 預算

設定的「預算」內頁（統計幣別、**只算支出，不扣收入**；輸入框離開時儲存，空白是取消）：

- **月預算總額**（帳本文件 `monthBudget`）、**年預算總額**（`yearBudget`）、**各支出類別的月預算**（類別文件的 `budget`；年預算沒有分類拆分）。rules 驗證為正數，收入類別不能有預算。
- 等級與群組預算一致（`WARN_RATIO` 0.8、`OVER_RATIO` 1，來自 `src/utils/budget.js`）：已用 ≥ 80% 為接近、≥ 100% 為超支。月預算跟著「月開始日」的期間。
- 顯示：帳本主頁標題下一條細進度條與「預算已用 N%」（超支顯示超支金額），沒設月預算就不顯示；圖表頁「預算」卡（月視圖：總預算與有設定的分類；年視圖：年預算；收入分頁不顯示）。
- 沒有收入預算、結轉與通知。

## 類別（每個帳本各一份）

設定的「類別」內頁，用「支出／收入」切換，各一份清單：新增、改名、上移／下移、刪除；名稱最多 20 字、同種類不可重名、每種至少留一個、前端限制每種 30 個。

- 存成 `ledgers/{id}/categories/{文件id}`：`kind`、`key`（帳目 `category` 欄位存的值）、`name`（選填）、`order`。文件 id = `e_`／`i_` 加 `key`（支出與收入都有 `other`，不會撞）；標準類別的 `key` 就是原本的代碼（`food`、`salary`…），自訂類別的 `key` 是 `c_` 加亂數，必須有名稱。rules 逐份驗證。
- **沒有任何類別文件的帳本直接用預設清單**（支出：餐飲、交通、住宿、購物、娛樂、日用品、醫療、其他；收入：薪資、獎金、投資、退款、其他），既有帳本與帳目不用遷移；第一次編輯時才把整份預設清單一次寫成文件，再套用修改。
- 顯示名稱（`categoryName`）：有自訂名稱用它；標準類別沒有名稱用翻譯；**已刪除的自訂類別顯示「其他」**；舊的自由文字原樣顯示。刪除類別不改動任何帳目。
- 群組同步來的帳目：類別在帳本清單裡有同 `key` 就沿用，**對不到（含已刪除、群組的自訂文字）一律歸「其他」**；你在群組帳目上改過的類別不會被覆寫。
- 記帳面板、帳本主頁、圖表、群組帳目面板與 CSV 匯出都用帳本的類別名稱。
- 類別圖示還沒做。

## 固定收支與固定轉帳

設定的「固定收支與轉帳」內頁，規則存在 `ledgers/{id}/recurring/{id}`：種類（支出／收入／轉帳）、名稱、帳戶（轉帳另有轉入帳戶）、金額、類別、備註、頻率（每天／每週／每月／每年）、起始日、結束日（選填）、每月幾日（1–28 或月末）、統計匯率 `rate`（帳戶幣別與統計幣別不同時）、啟用狀態、`generatedThrough`（已產生到哪個原定日期）。

- **沒有後端排程**：網頁在關掉時無法在背景執行，所以改成**開啟帳本時補入**到今天為止漏掉的項目（`useRecurringRun`，每個帳本每次使用自動跑一次，新增或修改規則後立刻再跑）。久沒開也只是補多一點：每月一筆 5 年才 60 筆，每日 5 年約 1,900 筆（切成 200 筆一個交易），每次開啟最多補 1,000 筆，其餘下次再補。排程函式不採用的原因見下方「為什麼不用排程」。
- **不會重複入帳**：帳目 id 是 `r_{規則id}_{原定日期}`；每個區塊在同一個 Firestore 交易裡確認規則的 `generatedThrough` 沒變、寫入帳目、用 `increment` 更新帳戶餘額、推進 `generatedThrough`，所以重複開啟或同時開兩個分頁都不會重複（實測兩個分頁同時開只入帳一次）。
- **幣別**：固定是帳戶幣別；固定轉帳兩個帳戶必須同幣別，轉入金額等於轉出金額；帳戶幣別與統計幣別不同時，統計金額用規則上固定的 `rate`（建立時帶入當時匯率，可改）。
- **編輯與刪除**：只影響之後；已產生的帳目是一般帳目（來源 `recurring`，明細標示「固定」，可編輯與刪除）。起始日建立後不可改。停用期間不補，重新啟用時從昨天之後算起。起始日在過去時，建立前會預覽「會補入 N 筆」。
- **假日調整**（進階分頁，整個帳本一個設定）：不調整、提前到前一個工作日、延後到下一個工作日；只改帳目的 `date`，id 與原定日期（`source.scheduled`）不變，所以假日資料更新不會讓 id 漂移；已產生的帳目不被新設定改動。
- **月曆顯示假日**：帳本主頁的月曆把假日的日期數字標成紅色（週六日、國定假日、補假；補班日不標紅），當日明細標題在日期旁顯示名稱（例如「國慶日」「補行上班日」）。每次開啟主頁會載入畫面涵蓋年份的資料（`useHolidays`，沿用下面的快取，與有沒有設定假日調整無關）；沒有資料或抓不到時退回把週六日標紅、不顯示名稱。
- **假日資料**（`holidays.js`）：開源資料集 `ruyut/TaiwanCalendar` 的整年 JSON（先試 jsDelivr，再試 GitHub raw；已含週末、補假與補班日），月曆與假日調整共用，一年抓一次、存在瀏覽器 `localStorage` 快取 30 天，沒有該年資料（404）快取一天。這不是官方 API；沒有資料、抓不到或格式不對時，該年退回「週六日是假日」，固定收支不會因此壞掉。

### 為什麼不用排程

排程函式需要 Cloud Scheduler（額外啟用 API 與權限，部署失敗會連帶影響其他函式，專案之前已決定不用），後端要再寫一份產生邏輯（`functions/` 不能引用 `src/`），還要每天掃所有人的規則；而個人帳本只有本人看得到，沒開 App 時沒產生不會影響任何人。之後若需要推播等功能，可以用 GitHub Actions 排程腳本（像清除合併備份那樣）搭配同一套計算。

## 期間（月開始日、週開始日、年開始月）

設定頁「進階」分頁，存在帳本文件的 `monthStartDay`、`weekStartDay`、`yearStartMonth`（選填，沒填是日曆月份、日曆年、週日開頭，既有帳本不受影響）。只影響月曆、總計與圖表怎麼分月，帳目資料不變；rules 驗證 `monthStartDay` 為 0–28 的整數、`weekStartDay` 為 0／1／6、`yearStartMonth` 為 1–12。

- **月開始日**：1–28 是每月幾日，`0` 是月末（每月最後一天）。期間 `YYYY-MM` 從該月的起始日開始，到下一個期間起始日的前一天，以「起始日所在的月份」命名：每月 5 日 → `2026-11` 是 11/5–12/4；月末 → `2026-11` 是 11/30–12/30（每月的長度隨月份變）。不開放 29–31 是因為短月份沒有那一天，要用月末取代。
- **週開始日**：週日、週一、週六，影響月曆星期標題與第一週的補格。
- 實作：`dates.js` 的 `periodStart`、`periodBounds`、`monthKeyOf(date, 起始日)`、`shiftMonthDate`、`dateForMonth`，`summary.js` 的 `monthDateBounds`、`monthGrid(monthKey, 起始日, 週開始日)`；查詢仍是單一欄位 `date` 的範圍，不需要索引。主頁與圖表的標題在起始日不是 1 時顯示範圍（例如 11/5–12/4），月曆跨月時每月 1 日的格子標成「12/1」。
- 趨勢圖的月份切換、月份選擇器都跟著期間；帳戶頁、淨資產與帳目本身不受影響。
- **年開始月**：1–12，存 `yearStartMonth`（選填，預設 1）。年期間 `YYYY` 從該年「年開始月」的月期間起點，到 12 個月後的月期間起點前一天，以起始年命名：年開始月 4、月開始日 5 → `2026` 是 2026-04-05 到 2027-04-04。

## 連結分帳群組

設定頁「分帳」分頁：每列左邊群組下拉、右邊開關；底下分隔線後有「重新整理」與靠右的「匯入到帳戶」。

- **開啟**：寫入 `groupLinks/{群組id}` 與快照帳戶 `snap_{群組id}`（種類 `group`、幣別 = 統計幣別）。範圍是**群組的全部帳目，含連結前的歷史**（2026-11-25 起；原設計是「不帶歷史」，實測連結既有旅程群組會同步 0 筆，改掉了）。`linkedAt` 寫成最早的時間（epoch），同步時一律忽略，舊版連結存的「按下開關的時間」也不再限制範圍。
- **同步內容**：每筆群組帳目中「我的分攤」（`splits[uid]`，為 0 或贊助不產生），固定 id `g_{群組}_e_{帳目}`／`g_{群組}_i_{帳目}`，重複同步只是覆寫。外幣帳目的原幣份額 = `originalAmount × 分攤 ÷ 總額`；統計金額用群組基準幣的分攤，兩邊基準幣不同時優先用帳目的 `homeRate`（`homeCurrency` 等於統計幣別時），否則用同步當下的匯率並**凍結**（份額沒變就不重算）。
- **0 筆時的說明**：設定頁的連結列會說明「群組有 N 筆帳目，但沒有一筆分攤到你」或「群組還沒有帳目」，方便判斷原因。
- **時機**：開啟帳本時每個群組同步一次（`useLedgerSync`，一次性 `getDocs`，先比對再寫，只寫有變動的），之後按「重新整理」；其他成員記帳後需重新整理或重開。來源被刪或日期被改到連結前，快照帳目會被刪除。
- **快照帳目**：不影響任何帳戶餘額、不計入淨資產，但統計（圖表）會計入。點開是唯讀面板：金額、日期、標題來自群組；**分類與備註可改**，改過的記在 `source.edited`，之後同步不再覆寫。
- **關閉**：確認後刪除快照帳戶、尚未匯入的快照帳目與連結（改過的分類備註一併消失）；已匯入的一般帳目保留。
- **匯入到帳戶**：選群組與一般帳戶，預覽筆數與餘額變動；帳目與目標帳戶幣別不同時顯示匯率（自動帶入、可修改，抓不到要手動輸入），只新增 `accountAmount`／`accountRate`，統計金額不變。帳目以固定 id 就地改成 `detached` 一般帳目（可編輯、計入餘額、不再同步，編輯時保留 `source` 與標題），分批寫入並以 `increment` 更新餘額與快照帳戶；完成後詢問是否停止同步。
- **無法讀取的群組**（已退出或已刪除）：不動既有快照帳目，顯示提示，使用者可匯入保留或關閉同步。

## 匯出 CSV

設定頁「資料」分頁，匯出**整個帳本**的全部帳目（不提供範圍選項），日期由舊到新。欄位：類型、日期、標題、類別、帳戶、金額、幣別、統計金額（統計幣別）、扣款金額（跨幣別才有）、轉入帳戶、轉入金額、備註、來源（手動／固定收支／群組同步／群組（已匯入））。格式沿用群組匯出：開頭 BOM（Excel 不亂碼）、以 `=+-@` 開頭的文字補單引號、金額一律正數。

- 一般瀏覽器直接下載；LINE 內建瀏覽器無法下載 blob，改呼叫 `exportCsv`（傳 `ledgerId`），後端驗證帳本屬於呼叫者後存到 `exports/{uid}/{ledgerId}/`，回傳 5 分鐘有效的簽名網址，由使用者貼到手機瀏覽器開啟。檔案 1 天後由 bucket 生命週期規則清除。
- 讀取：按下匯出時 `getDocs` 讀整個帳本的帳目。

## 備份與還原

設定頁「資料」分頁的「備份與還原」，以**單一帳本**為單位：

- **下載備份**：JSON 檔（`format: catsplit-ledger-backup`、`version: 1`），內容是帳本設定（名稱、統計幣別、期間、預算、假日調整）、帳戶、帳目、類別（含預算）、固定項目規則（含進度）。**不含**群組同步的快照帳戶與快照帳目、群組連結：還原後重新連結群組就會同步回來；已匯入成一般帳目的群組帳目有備份。LINE 內建瀏覽器無法下載檔案，和 CSV 一樣改呼叫 `exportCsv`（`ledgerId` 加 `format: 'json'`，上限 300 萬字元）取得 5 分鐘有效的下載網址。
- **從檔案還原**：一律建立成**新帳本**（名稱加「（還原）」），不動現有帳本。選檔後先整份驗證（格式版本、帳戶引用、id 不重複、數量上限：帳目 4 萬筆、檔案 20 MB），沒過就說明原因、什麼都不寫；通過後顯示摘要（帳戶數、帳目數、日期範圍）讓你確認。
- **寫入**：先分批（每批 400）寫類別、帳戶、固定項目、帳目，**最後才寫帳本文件**；中途失敗（網路、rules 拒絕）時呼叫 `deleteLedger` 清掉已寫的部分，不會留下半套資料。帳戶餘額依期初餘額與帳目**重新計算**，不採信檔案裡的 `balance`；帳目的建立時間與固定項目的進度保留，所以還原後固定收支不會重複產生。全部走現有的 rules，沒有新增 rules。
- 受帳本數量上限（20 個）限制。

## 刪除

- **帳本改名與刪除**：帳本選單（左上圓鈕）每個帳本旁的鉛筆，展開名稱（統計幣別唯讀）與「刪除這個帳本」，至少要保留一個。客戶端不能刪帳本文件（rules 擋掉），由後端 `deleteLedger` 用 `recursiveDelete` 刪整棵子樹（帳戶、帳目、類別、固定項目、群組連結），沒有 500 筆上限。備份還原中途失敗時也用它清除寫到一半的資料。
- **刪除我的資料**：`detachMember`（`deleteAccount: true`）在刪 Auth 之前先刪 `users/{uid}/ledgers`，失敗就不刪帳號，使用者可以重試。
- 後端邏輯在 `functions/ledgerOps.js`，整合測試 `functions/emulator-tests/ledgerOps.mjs`（`npm run test:merge`）。

## 帳號合併

`movePersonalData` 遞迴搬移整棵 `users/{uid}`，帳本子樹連同 id 一起搬，帳目裡的 `accountId` 不會失效。

兩個帳號都開過帳本時，雙方的預設帳本（`default`）與現金帳戶（`cash`）是固定 id，會落入衝突處理，預設保留「保留帳號」那一份，帳戶 `balance` 因此不會相加。處理方式：`movePersonalData` 對雙方都有的帳本，搬完帳目後在後端（`functions/ledgerOps.js` 的 `recomputeLedgerBalances`）依帳目重算帳戶餘額；兩邊連結同一個群組時 `groupLinks` 取較早的 `linkedAt`。設定頁「資料」分頁的「重新計算餘額」仍可手動修復。群組同步帳目的份額在合併後由下一次同步依新的分攤改寫。類別文件 id 是固定的（例如 `e_food`），雙方都編輯過類別時衝突的文件保留「保留帳號」那一份；固定項目規則是自動 id，不會衝突，直接搬過來。
