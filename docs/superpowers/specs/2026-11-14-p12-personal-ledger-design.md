# P12 個人記帳（設計）

日期：2026-11-14　修訂：2026-11-24　狀態：決定已確認，待實作
前置：整體架構決策見 [`../archive/2026-11-14-p14-identity-design.md`](../archive/2026-11-14-p14-identity-design.md)（同一專案、功能模組分界、不拆微服務）。P14 已上線；P18 第一階段已上線，底部導覽列的「記帳」Tab 目前是 `/ledger` 佔位頁，本項完成後取代它。實作順序見[計畫](../plans/2026-11-24-p12-ledger-plan.md)。

## 目標

個人可以建立**多個帳本**（每個帳本一趟旅程或一個用途），各自有帳戶與多幣別帳目，並可把分帳群組的「我的分攤」自動同步進來：

```
匯率換算 ──「記一筆」──▶ 個人帳本 ◀──自動同步「我的分攤」── 已連結的分帳群組
```

## 已確認的決定

| 項目 | 決定 |
|---|---|
| 結構 | 帳本 → 帳戶、帳目、群組連結，**巢狀子集合**（`users/{uid}/ledgers/{id}/…`） |
| 多帳本 | 一個使用者可有多個帳本，前端限制 20 個；帳本頁左上角切換與新增；第一次進入自動建立「我的帳本」與「現金」帳戶 |
| 統計幣別 | 每個帳本一個 `baseCurrency`，建立後不可改 |
| 帳戶 | 全新的 `accounts` 集合，**不沿用 `spendMethods`、也不搬移**；每個帳戶單一幣別、建立後不可改；`balance` 在記帳時以 `increment` 維護，另提供「重新計算」修復 |
| 幣別模型 | 每筆帳目記**實際花的幣別與金額**（可自選，預設帶帳戶幣別）與當下匯率：`baseAmount` 換成帳本統計幣別（統計只加總它、之後不重算），`accountAmount` 是對帳戶餘額的影響（帳戶幣別）。轉帳維持轉出與轉入兩個金額，不需要匯率 |
| 群組互通 | 在帳本設定連結群組，同步連結之後的分攤，全部進**快照帳戶**；每筆群組帳目對應一筆個人帳目 |
| 口徑 | 分攤口徑：取 `splits[uid]`；群組的轉帳結算不進個人帳本；群組收入一併帶入，贊助（`isSponsorship`）不帶 |
| 歷史 | 不帶歷史：只同步**消費時間**（`createdAt`）在連結時間之後的帳目 |
| 快照帳戶 | 不能手動記帳、不計入淨資產、**不影響任何帳戶餘額**；關閉同步就刪除快照帳戶與其帳目（需確認） |
| 匯入到帳戶 | 旅程結束時可把快照**覆寫匯入**某個帳戶：帳目變成一般帳目（不再同步、可編輯、計入餘額）；匯入完成後詢問是否停止同步 |
| 導覽 | 首頁／帳本／記帳（中間凸起）／帳戶／設定；帳本頁左上帳本切換、右上圖表 |
| 帳本主頁 | 上半月曆（有帳目的日期下方一個點）、下半是選取日期的支出、收入、轉帳明細 |
| 分類 | 記帳面板用**下拉選單**選類別，不放圖示、不提供「自訂」輸入。預設清單：支出沿用群組的 7 個分類（餐飲、交通、住宿、購物、娛樂、日用品、醫療）；收入用薪資、獎金、投資、退款、其他。使用者自訂分類改在**設定頁管理**（之後再做，第一版只有預設清單）；分類圖示之後再單獨處理 |
| 記帳面板 | 底部彈出面板、金額最先、常駐數字鍵盤（內建算式）；日期整行、類別與帳戶並排下拉、其餘空間留給備註；不做收據照片。細節見 3.1 |
| 預算、訪客 | 預算延後（等 P8）；訪客不能使用 |

## 1. 資料模型

```
users/{uid}/ledgers/{ledgerId}                       帳本
users/{uid}/ledgers/{ledgerId}/accounts/{accountId}  帳戶
users/{uid}/ledgers/{ledgerId}/transactions/{id}     帳目
users/{uid}/ledgers/{ledgerId}/groupLinks/{groupId}  群組連結
```

只有本人可讀寫，訪客拒絕。選巢狀而不是 `transactions` 加 `ledgerId` 欄位，是因為：月份查詢只用單一欄位範圍，**不需要複合索引**（CI 不會部署索引）；刪除帳本就是刪一棵子樹。代價是跨帳本總覽需要 collection group 查詢，第一版不做。

### 1.1 `ledgers/{ledgerId}`

| 欄位 | 說明 |
|---|---|
| `name`、`icon`、`color` | 名稱（≤ 20 字）、圖示、顏色（沿用群組圖示選擇器） |
| `baseCurrency` | 統計幣別（`CURRENCIES` 的代碼），已有帳目後不可改 |
| `archived`、`createdAt` | 封存旗標、建立時間 |

### 1.2 `accounts/{accountId}`

| 欄位 | 說明 |
|---|---|
| `name`、`type` | 名稱（≤ 20 字）、類型（現金、銀行、信用卡、電子票證、其他） |
| `currency` | 帳戶幣別，建立後不可改 |
| `initialBalance`、`balance` | 初始餘額（信用卡可為負）、目前餘額 |
| `kind` | `normal` 或 `group`（快照帳戶，系統管理） |
| `syncedCount`、`syncedNet` | 僅快照帳戶：同步筆數與淨額（同步時一併累加，帳戶頁顯示用） |
| `archived`、`createdAt` | 有帳目的帳戶不能刪除，只能封存 |

快照帳戶的 id 固定為 `snap_{groupId}`，重複連結不會產生第二個；幣別固定為帳本的統計幣別。

### 1.3 `transactions/{id}`

| 欄位 | 說明 |
|---|---|
| `type` | `income`、`expense`、`transfer` |
| `accountId` | 帳戶 |
| `currency`、`amount` | **實際花的幣別與金額**（預設帶帳戶幣別，可自選）；轉帳時是轉出帳戶的幣別與轉出金額 |
| `exchangeRate`、`baseAmount` | 入帳當下的匯率與換成帳本統計幣別的金額；同幣別時匯率 1。轉帳不計入收支，不需要 |
| `accountAmount`、`accountRate` | 對帳戶餘額的影響（帳戶幣別）。`currency` 等於帳戶幣別時等於 `amount`，可省略；不同時由 `accountRate` 換算，**可手動改成實際扣款金額**（例如刷卡的手續費）。轉帳不用 |
| `toAccountId`、`toAmount` | 僅轉帳；轉入帳戶與轉入金額（轉入帳戶幣別），跨幣別時與轉出金額不同 |
| `title`、`category`、`note`、`date`、`createdAt` | 標題、分類（內建代碼或自訂文字）、備註（≤ 50 字）、`YYYY-MM-DD`、建立時間 |
| `source` | `{ type: 'manual' \| 'fx' \| 'group', groupId?, kind?, itemId?, detached?, edited? }` |

- **統計只加總 `baseAmount`**，不重算匯率。這和分帳「`originalAmount` + `exchangeRate` + `amount`」是同一個邏輯；個人帳本多了 `accountAmount`，因為帳戶有真實餘額：每筆都記下當時的匯率與兩個金額，之後匯率怎麼變，統計與餘額都不會被牽動（例如日圓現金剩多少日圓，就是 `accountAmount` 的加總）。
- **跨幣別的帳目**（例如 TWD 信用卡刷日圓商品）：記 ¥14,500 與當下匯率，`accountAmount` 由 `accountRate` 估算出來；實際扣款金額與估算不同時（手續費、結算匯率）可手動覆寫，餘額才不會和帳單差太多。
- **分類**：支出沿用 `DEFAULT_CATEGORIES`（含自訂文字）；個人收入用新的一組：薪資、獎金、投資、退款、其他。群組收入的分類對不上的歸「其他」。
- **餘額**：記帳、編輯、刪除時在同一個 batch 用 `increment` 更新帳戶 `balance`（增量是 `accountAmount`，沒有時用 `amount`；轉帳更新兩個帳戶，分別用 `amount` 與 `toAmount`）。**同步中的快照帳目不碰任何 `balance`**，所以同步不會造成餘額漂移。提供「重新計算」按鈕，讀該帳戶全部帳目重算 `balance` 作為修復。
- `groupLinks` 不需要全域唯一：同一個群組可以連結到不同帳本（各自獨立）。

### 1.5 rules 的實作細節（PR1 已上線）

與上面欄位表一致，另有幾點比 spec 文字更嚴或有取捨：

- 貨幣欄位只驗證「3 碼字串」，清單比對（`CURRENCIES`）在前端，避免新增貨幣時 rules 也要同步部署。
- **客戶端不能刪帳本文件**（只能由後端 `recursiveDelete`）；帳戶、帳目、群組連結本人可刪。「有帳目的帳戶不能刪」只能在前端擋。
- 帳本的 `baseCurrency`、帳戶的 `currency` 與 `kind`、帳目的 `createdAt` 在 rules 層級**建立後一律不可改**（即使還沒有帳目）。
- 快照帳戶的 `kind` 與 `type` 必須同為 `group`；`source` 為必填（手動帳目寫 `{ type: 'manual' }`）。
- 收入與支出必須有 `exchangeRate` 與 `baseAmount`，不能有轉帳欄位；轉帳必須有 `toAccountId`（不可等於 `accountId`）與 `toAmount`，不能有匯率、統計金額與扣款金額。
- 所有欄位都有白名單（`hasOnly`），之後新增欄位要同步改 rules。

### 1.4 `groupLinks/{groupId}`

`{ linkedAt, groupName }`。`linkedAt` 是「不帶歷史」的分界；`groupName` 是快取，群組失效後設定頁仍能顯示。

## 2. 群組同步

### 2.1 同步的內容

每筆在範圍內的群組帳目，在快照帳戶產生一筆個人帳目：

| 來源 | 個人帳目 id | `type` | 金額 |
|---|---|---|---|
| `groups/{g}/expenses/{e}` | `g_{g}_e_{e}` | `expense` | `splits[uid]`（為 0 或不存在則不產生） |
| `groups/{g}/incomes/{i}` | `g_{g}_i_{i}` | `income` | `splits[uid]`；贊助不產生 |

- 日期、標題、分類沿用群組帳目；`source = { type: 'group', groupId, kind, itemId }`。
- **幣別**：快照帳目的 `currency`、`amount` 是**該筆群組帳目原幣下我的份額**（`originalAmount × splits[uid] ÷ amount`）；`baseAmount` 由 `splits[uid]`（群組基準幣）換成帳本統計幣別：同幣別匯率 1，不同時若帳目的 `homeCurrency` 等於統計幣別就用 `homeRate`，否則用**首次同步當下**的匯率。已同步帳目的匯率凍結，只有分攤金額改變時才重算。快照帳目沒有 `accountAmount`，匯入時才產生。快照帳戶的幣別是帳本統計幣別，只用來顯示淨額。
- 群組收入與支出一樣有 `splits`，收入取 `splits[uid]`。

### 2.2 唯讀規則

同步帳目的**金額、幣別、日期、標題不能在個人帳本編輯**（要改請到群組改，下次同步會更新）。**分類與備註可以改**，改過的欄位記在 `source.edited`，之後同步不再覆寫該欄位。

### 2.3 同步時機與範圍

- 開啟帳本時同步，**範圍是連結之後的全部**：查詢 `createdAt >= linkedAt`。旅程帳本的範圍有上限，不需要月份視窗；日後若有長期連結的大群組造成讀取量過大，再加月份視窗。
- 一次性讀取（`getDocs`），同一次使用內只同步一次，另提供手動「重新整理」；先比對現有快照帳目，只寫有變動的。
- **偵測被刪除的帳目**：查詢涵蓋連結後的所有日期，所以快照中「來源是這個群組、尚未匯入（非 `detached`）、但查詢結果沒有」的帳目，只可能是來源被刪了，或消費日期被改到連結之前，兩者都直接刪除。
- **無法讀取的群組**（本人已退出或群組已刪除）：該群組的快照帳目不再同步，帳本頁提示一次，使用者可以選擇匯入到某個帳戶保留，或關閉同步刪除。
- 同步時一併更新快照帳戶的 `syncedCount`、`syncedNet`。

### 2.4 連結、關閉與匯入

- 帳本設定頁「連結群組」：每一列左邊是下拉選單（選分帳群組）、右邊是開關。打開時寫入 `groupLinks` 與快照帳戶，開始同步。要連結多個群組就多一列。
- **關閉同步**：確認後刪除快照帳戶與其尚未匯入的帳目（已匯入的一般帳目保留）。確認訊息要寫明刪什麼，並提醒在這些帳目上改過的分類與備註也會刪除。
- **匯入到帳戶**（列表底下分隔線後、靠右的按鈕）：選一個該帳本的一般帳戶，把該群組的快照帳目**覆寫匯入**：
  - 帳目以固定 id 就地更新：`accountId` 改成目標帳戶、`source.detached = true`，之後變成一般帳目（不再同步、可編輯）。
  - 目標帳戶的 `balance` 以 `increment` 加上淨額（分批寫入，每批 ≤ 400）。
  - 金額換算：每筆帳目保留原幣 `currency`、`amount` 與 `baseAmount` 不變，只新增 `accountAmount`：目標帳戶幣別與 `currency` 相同時直接等於 `amount`，不經過匯率；不同時用匯率換算（`accountRate`），匯入前顯示匯率讓使用者確認。
  - 匯入後詢問「要停止同步這個群組嗎？」；不停止的話，之後新的群組帳目會再進快照。重複匯入是覆寫，不會重複入帳。

## 3. 介面與流程

互動線稿（示意資料）：https://claude.ai/artifact/WJXS5FP7VGdjiLVYZuxJ4M ；畫面細節慢慢調，下列只定骨架。

- **帳本導覽列**：首頁、帳本、記帳（中間凸起的動作鈕，開啟記帳面板）、帳戶、設定。進入 `/ledger/*` 後不顯示全站的 `MainTabBar`，「首頁」回到分帳首頁。
- **路由**：`/ledger`（帳本主頁，導向最近使用的帳本）、`/ledger/accounts`、`/ledger/stats`、`/ledger/settings`、`/ledger/new`、`/ledger/:id/edit`。目前帳本 id 存在本機（`localStorage`），不同步到帳號。
- **帳本主頁**：header 左上圓鈕切換或新增帳本（顯示帳本名稱與統計幣別），右上圓鈕進圖表；月份切換；支出、收入、結餘三欄同樣小字置中；上半月曆（有帳目的日期下方一個點，今天有外框、選取的日期填色）；下半是選取日期的明細，標題列顯示當日小計。同步帳目標示「來自群組」並鎖定。
- **記帳面板**：見 3.1。

### 3.1 記帳面板（體驗已確定，互動線稿 v4）

參考使用者平常用的記帳 App：日期、金額、類別、帳戶、計算機這幾列（沒有成員）。與分帳的新增頁不同，個人記帳每天記好幾筆，所以目標是**點最少下完成一筆**。

- **容器**：從底部彈出的面板，背景保留帳本；點背景或 ✕ 關閉；儲存後回到帳本，新帳目立刻出現在月曆與當日明細。同步帳目不能在面板編輯金額與日期。
- **版面（由上到下）**：支出／收入／轉帳切換；**第一行**整行日期（字稍大，點了跳出日期選擇框）；**第二行**左邊類別下拉、右邊帳戶下拉；**第三行起到金額列之前**整塊都是備註（選填，最多 50 字）；金額列（幣別選單＋算式與結果）；換算資訊；常駐數字鍵盤；底部「再記一筆／儲存」。轉帳時第二行改為轉出與轉入帳戶（中間有對調鈕），沒有類別。
- **順序與預設**：金額最先；日期預設帶月曆選取的那天；帳戶與類別預設帶**上次用的**（每個帳本各記一份，存本機）；標題不必填，沒填就用分類名稱。
- **數字鍵盤**：0–9、小數點、⌫、＋−×÷。有運算時主按鈕變「＝」，先算出結果再按儲存；「再記一筆」在有運算或金額為 0 時停用。**不用 `eval`**，算式解析寫成純函式並測試；單一數字最長 9 位。
- **幣別**：金額列左側的幣別選單，**完整貨幣清單**、常用幣別置頂，沿用分帳的 `CurrencySelect`（線稿只列了幾種是示意）。預設帶帳戶幣別，使用者手動選過幣別就不再隨帳戶變動。幣別與統計幣別不同時，顯示統計用換算與匯率；與帳戶幣別不同時多一列「扣款金額」，以匯率估算當 placeholder，可手動覆寫。平常看不到這些列。
- **轉帳**：轉出與轉入帳戶上下排列、中間有對調鈕，兩者不能相同；金額列幣別固定為轉出帳戶；跨幣別多一列「轉入金額」。
- **分類**：下拉選單只顯示類別名稱，不帶圖示。使用者自訂分類改在設定頁管理（之後做；資料存放位置到時再定，帳目的 `category` 維持「內建代碼或自訂文字」）。
- **不做**：收據照片、分享到 LINE、標題必填、面板內自訂分類。
- **帳戶頁**：淨資產（依匯率估算成統計幣別，外幣標註）、帳戶清單與餘額（各自幣別）；快照帳戶獨立一區，標示不計入淨資產，顯示筆數與淨額。
- **圖表頁**：分類占比、近 6 個月支出趨勢；從帳本主頁右上圓鈕進入，返回帳本。
- **設定頁**：連結群組（下拉＋開關、匯入到帳戶按鈕）、統計幣別（已有帳目時唯讀）、分類管理（之後：使用者自訂分類）。
- **新增帳本**：名稱、圖示、統計幣別（建立後不可改，要先說明）。

## 4. rules、測試、刪除

- **rules**：`ledgers`、`accounts`、`transactions`、`groupLinks` 僅本人可讀寫且為非訪客（`isMember()`）；驗證 `type`、`currency` 在 `CURRENCIES` 內、`amount`、`baseAmount` 為大於 0 且小於 1e12 的數字、名稱長度。補 `firestore-tests/ledger.rules.mjs`。不需要新索引。
- **單元測試**（同步與換算邏輯寫成純函式）：依消費時間與 `linkedAt` 篩選、分攤為 0 與贊助不產生、固定 id 冪等、來源刪除或日期移到連結前的處理、`edited` 不被覆寫、匯率凍結、同步帳目的原幣份額換算、匯入的 `accountAmount`（同幣別與跨幣別）與 `balance` 增量、帳戶餘額維護（含跨幣別帳目與轉帳）、手動覆寫扣款金額、統計幣別已有帳目時不可改。
- **刪除**：帳目沒有上限，**刪除帳本與「刪除我的資料」都走後端 `recursiveDelete`**（比照 `deleteGroup`，新增一支 Cloud Function），不用前端分批。`public/privacy.html`（中英文）補寫個人帳本資料。
- **帳號合併**：`movePersonalData` 遞迴搬移整棵 `users/{uid}`，帳本子樹連同 id 一起搬，`accountId` 不會失效；`groupLinks` 兩邊都有同一個群組時取較早的 `linkedAt`，要另外處理並補測試。
- **文件**：新增 `docs/guides/personal-ledger.md`，更新 `README.md`、`docs/guides/data-model.md`。

## 風險

- 餘額用 `increment` 維護，與群組彙總一樣有漂移風險，所以要有「重新計算」；同步不碰餘額以降低風險。
- `accountAmount` 是用匯率估算的，可能與銀行或信用卡帳單有小差異；介面要讓使用者能看到並覆寫。
- 同步由本人的前端執行，其他成員記帳後要等本人下次開啟帳本才會看到；介面要有「重新整理」。
- 匯入分批寫入（每批 ≤ 400）時中途失敗：因為是固定 id 就地更新，重新匯入即可補完，但 `balance` 的增量要與實際更新的帳目一致，需先算好再一起寫，或匯入後執行一次重新計算。
- 帳本與帳戶數量沒有 rules 層級的上限，只能在前端限制。
- 在 LINE 內建瀏覽器的行為要在每個階段上線後實測。
