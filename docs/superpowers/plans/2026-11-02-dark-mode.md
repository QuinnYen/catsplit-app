# 暗黑模式 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓使用者在設定頁切換「跟隨系統／淺色／深色」，整個 App 的所有頁面與彈窗跟著換色。

**Architecture:** 色碼改成 CSS 變數：`:root` 放淺色值，`:root[data-theme="dark"]` 覆寫成深色值。`ThemeProvider` 決定實際主題並寫到 `<html data-theme>`，`index.html` 內嵌腳本在畫面繪製前先設好以免閃白。約 700 處寫死色碼用一次性的 codemod 依屬性替換（`#fff` 當文字色時不換），再用 `check:colors` 掃描殘留並逐一人工處理。

**Tech Stack:** React 19、CSS custom properties、`node --test`、`espree`（專案已有，`check-cjk` 在用）。

**Spec:** `docs/superpowers/specs/2026-11-02-dark-mode-design.md`

## Global Constraints

- 三種模式 `'system' | 'light' | 'dark'`，預設 `system`；設定只存 `localStorage` key `cs-theme`，不動 Firestore。`localStorage` 不可用（無痕模式）時不能丟錯，退回 `system`。
- 橘色品牌色（`#FF8C42`、`#FF6B1A`）、橘色頁首漸層與其上的白字、LINE 綠 `#06C755` 兩種模式下不變。
- 淺色模式外觀不變：每個變數的淺色值等於它取代的原色碼（合併近似色時以最常用者為準）。
- 不在範圍內：`public/` 靜態頁、`src/utils/flexMessages.js`、`src/utils/shareContent.js`（LINE 訊息）、`src/components/CropModal.jsx`（裁切畫面本來就是黑底）。
- 所有可見文字走 `t()`，zh-TW 與 en 字典 key 與佔位符一致；程式裡不得寫死中文（`npm run check:cjk`）。
- 樣式沿用既有慣例：行內 style，不新增 CSS 檔；新增的全域規則只寫在 `src/index.css`。
- 直接在 `main` 上作業（使用者的做法）；Checkpoint 步驟只列出改動檔案，commit 由使用者自己下。

## Review Focus

- 白字被誤換成卡片底色：`color: cond ? '#fff' : '#b08060'` 這類三元式裡的 `#fff` 是文字色，換成 `var(--cs-card)` 後深色模式會變成深字壓在橘底上。Task 5 的替換報告要列出所有「#fff 換成卡片變數、但最近的屬性鍵不是 background／border 類」的位置，Task 7 逐一確認。
- 載入閃白：深色使用者重新整理時，App 載入前就必須是深色（Task 3 的內嵌腳本）。
- `system` 模式下系統主題中途切換，畫面要即時跟著變，不需重新整理（Task 1 測試 `resolveTheme`，Task 8 手動驗證）。
- `localStorage` 讀寫丟錯（無痕模式）或存了非法值：不能白畫面，退回 `system`（Task 1 測試 `normalizeMode`）。
- 原生控制項：日期選擇器、`<select>` 下拉選單、輸入框在深色下不能出現白底白字（Task 3 的 `color-scheme: dark`，Task 8 驗證）。
- 以 JS 計算或存成資料的顏色：統計頁圖表、群組圖示配色、`Avatar` 底色，不是 style 裡的字面字串，codemod 掃不到（Task 6、7 處理）。
- `check:colors` 的誤報與漏報：`#fff` 的屬性判斷、字串內含多個色碼的 `linear-gradient(...)`、template literal（Task 2 的測試案例涵蓋）。

### Task 1: 主題判斷純函式

**Files:**

- Test: `src/theme/theme.test.js`（風格同 `src/utils/budget.test.js`）

**Interfaces:**
- Produces:
  - `THEME_STORAGE_KEY = 'cs-theme'`
  - `normalizeMode(value: unknown): 'system' | 'light' | 'dark'` — 只有 `'light'`、`'dark'` 原樣回傳，其餘（`null`、`undefined`、亂碼、`'system'`）一律 `'system'`。
  - `resolveTheme(mode: 'system' | 'light' | 'dark', systemPrefersDark: boolean): 'light' | 'dark'` — `system` 依第二個參數，其餘原樣。

- [ ] **Step 1: 寫失敗測試**，名稱與斷言：
  - `normalizeMode 接受合法值`：`'light'` → `'light'`、`'dark'` → `'dark'`、`'system'` → `'system'`
  - `normalizeMode 非法值退回 system`：`null`、`undefined`、`''`、`'DARK'`、`'blue'`、`123` → `'system'`
  - `resolveTheme 手動模式不受系統影響`：`('light', true)` → `'light'`；`('dark', false)` → `'dark'`
  - `resolveTheme system 跟隨系統`：`('system', true)` → `'dark'`；`('system', false)` → `'light'`
- [ ] **Step 2: 執行確認失敗**：`node --test src/theme/theme.test.js`，預期 FAIL（找不到模組）。
- [ ] **Step 3: 實作上述兩個函式與常數於 `src/theme/theme.js`**。
- [ ] **Step 4: 執行確認通過**：`node --test src/theme/theme.test.js`，預期 4 個測試全部 PASS。
- [ ] **Step 5: Checkpoint**：列出 `src/theme/theme.js`、`src/theme/theme.test.js`。

### Task 2: `check:colors` 掃描器

**Files:**
- Create: `scripts/check-colors.mjs`、`scripts/check-colors.test.js`
- Modify: `package.json`（`scripts` 加 `"check:colors": "node scripts/check-colors.mjs"`）

**Interfaces:**
- Produces:
  - `findColors(source: string, file?: string): { line: number, text: string }[]` — 用 `espree.tokenize`（同 `scripts/check-cjk.mjs`）掃 `String`、`Template` token，找出字面的色碼（`#rgb`、`#rrggbb`，不分大小寫）與 `rgb(`／`rgba(`，排除 Palette 一節的「允許保留的原始色碼」。`#fff`／`#ffffff` 只有在**緊接的前兩個 token 是 `color` 識別字與 `:` 或 `=`** 時才允許（`color: '#fff'`、`color="#fff"`）；其他位置（包括三元式 `color: a ? '#fff' : x` 裡的 `#fff`）一律回報，由人確認。
  - `scanColors(roots?: string[]): string[]` — 掃 `src`（預設），略過 `src/utils/flexMessages.js`、`src/utils/shareContent.js`、`src/components/CropModal.jsx` 與 `*.test.js`，回傳 `檔案:行號: 內容` 字串陣列。
  - CLI：`node scripts/check-colors.mjs [目錄…]` 印出每筆與 `TOTAL n`，有命中則退出碼 1（同 `check-cjk.mjs` 的寫法）。

- [ ] **Step 1: 寫失敗測試**（`findColors`，輸入為小段 JS 原始碼字串），名稱與斷言：
  - `回報寫死的色碼`：`const a = { background: '#fff8f4' }` → 1 筆
  - `不分大小寫`：`'#F0D5C0'` → 1 筆
  - `允許品牌色`：`'#FF8C42'`、`'#ff6b1a'`、`'#06C755'`、`'#4caf50'` → 0 筆
  - `color 屬性的 #fff 允許`：`{ color: '#fff' }` 與 JSX `<X color="#fff" />` → 0 筆
  - `非 color 屬性的 #fff 回報`：`{ background: '#fff' }`、`{ border: '1px solid #fff' }` → 各 1 筆
  - `三元式裡的 #fff 回報`：`{ color: ok ? '#fff' : '#b08060' }` → 2 筆（`#fff` 與 `#b08060`）
  - `一個字串多個色碼`：`'linear-gradient(135deg, #FF8C42 0%, #fff8f4 100%)'` → 1 筆（只因 `#fff8f4`，品牌色不報）；且該筆的 `line` 正確
  - `允許半透明白與黑`：`'rgba(255,255,255,0.9)'`、`'rgba(0,0,0,0.4)'` → 0 筆；`'rgba(61,43,31,0.4)'` → 1 筆
  - `template literal`：`` `1px solid #f0d5c0` `` → 1 筆
  - `不報變數`：`'var(--cs-bg)'`、註解裡的 `// #fff8f4` → 0 筆
- [ ] **Step 2: 執行確認失敗**：`node --test scripts/check-colors.test.js`，預期 FAIL。
- [ ] **Step 3: 實作 `findColors`、`scanColors` 與 CLI**。判斷 `#fff` 允許與否時，只看 token 序列的前兩個 token，不做更複雜的推論。
- [ ] **Step 4: 執行確認通過**：`node --test scripts/check-colors.test.js`，預期全部 PASS；再執行 `npm run check:colors`，預期輸出大量命中與 `TOTAL <很多>`（此時尚未替換，這是正常的），退出碼 1。
- [ ] **Step 5: Checkpoint**：列出 `scripts/check-colors.mjs`、`scripts/check-colors.test.js`、`package.json`。

### Task 3: CSS 變數、ThemeProvider 與防閃白

**Files:**
- Modify: `src/index.css`、`index.html`、`src/main.jsx`
- Create: `src/theme/ThemeProvider.jsx`

**Interfaces:**
- Consumes: Task 1 的 `THEME_STORAGE_KEY`、`normalizeMode`、`resolveTheme`。
- Produces: `ThemeProvider({ children })`；`useTheme(): { mode, resolved, setMode }`，`mode` 為 `normalizeMode` 的結果，`resolved` 為 `'light' | 'dark'`，`setMode(next)` 會 `normalizeMode(next)` 後更新狀態並寫入 `localStorage`（寫入失敗只吞掉，同 `src/i18n/I18nProvider.jsx` 的做法）。在 `ThemeProvider` 之外呼叫 `useTheme` 要丟 `Error('useTheme must be used inside ThemeProvider')`。

- [ ] **Step 1: `src/index.css`** 在 `:root`（既有 `--tabbar-h` 那個區塊）加入 Palette 一節兩張表的**淺色值**（含 `--cs-gi-*`），並設 `color-scheme: light`；新增 `:root[data-theme="dark"]` 區塊放**深色值**並設 `color-scheme: dark`；再加 `:root[data-theme="dark"] body { background: var(--cs-bg); }`（只在深色動 body 底色，淺色維持現狀）。
- [ ] **Step 2: 實作 `ThemeProvider.jsx`**。初始 `mode` 讀 `localStorage`（try/catch）；`resolved` 由 `matchMedia('(prefers-color-scheme: dark)')` 與 `resolveTheme` 算出；`mode === 'system'` 時監聽 `change` 事件並在卸載時移除；`resolved` 變動時 `document.documentElement.dataset.theme = resolved`。
- [ ] **Step 3: `index.html`** 在既有內嵌腳本後再加一段內嵌腳本：讀 `localStorage['cs-theme']`（try/catch），值為 `'dark'` 或（非 `'light'` 且系統偏好深色）就設 `document.documentElement.dataset.theme = 'dark'`，否則設 `'light'`。邏輯與 `resolveTheme` 一致，註解標明兩處要同步。
- [ ] **Step 4: `src/main.jsx`** 以 `<ThemeProvider>` 包住 `<I18nProvider>`（最外層）。
- [ ] **Step 5: 驗證**：`npm run lint`、`npm test`、`npm run build` 皆通過。
- [ ] **Step 6: 手動驗證**：`npm run dev`，在瀏覽器開發者工具把 `<html data-theme="dark">` 加上去，確認 `body` 背景變深色、`color-scheme` 讓原生捲軸變深；重新整理，確認 `localStorage['cs-theme']='dark'` 時沒有閃白。
- [ ] **Step 7: Checkpoint**：列出本 Task 改動檔案。
